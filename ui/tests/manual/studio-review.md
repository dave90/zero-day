# Studio release walkthrough

A human developer/designer must review the actual application; screenshots and automated passes
alone are not a manual release pass. Copy the dated record template, identify the exact commit
and dirty-tree state, and attach evidence for each result.

Record: date, reviewer, build SHA, OS, browser/version, viewport/zoom, backend/model, fixture/live
status, scenario, expected/actual result, screenshots, defects, and retest result.

1. Independently launch Studio and the terminal CLI. Verify their behavior and cleanup.
2. Review 1100, 1280, 1440, 1728, 1920px and browser zoom: typography, contrast, alignment,
   independent scrolling, action visibility, keyboard-only operation, focus return, reduced motion.
3. Create the exact scoped Gruyere engagement, import context and a binary/source fixture.
4. Switch between simultaneous attacks immediately after typing; refresh; verify drafts and isolation.
5. Review all eight configuration sections and 38 options. Test invalid modes, empty model,
   unlimited children, host approval policy, and next-session configuration timing.
6. Run an explicitly authorized real Codex assessment. Compare selected/effective model,
   execution location, actors, tools and context usage to authoritative logs.
7. Deny one expected tool, allow another once, test an eligible session grant, and answer simultaneous
   questions. Refresh and use a second tab; stale decisions must never authorize new work.
8. Inspect each actor's memory/todos/tools and the attributed logs. Compare with actual files.
9. Review confirmed/pending/rejected/unscored/duplicate findings, evidence and report exports.
10. Ralph: revise an exact PRD revision, approve it, inspect independent coverage review, dossiers,
    pass snapshots, exhaustion and explicit additional-iteration resume.
11. Swarm: verify ownership bootstrap, per-peer caps, claims, messages, shared evidence, consolidation
    and Respond now. Do not infer coordination from freeform text alone.
12. Cancel a turn, follow up, close a session, inspect goal/session history, simulate a worker crash,
    restart service, and confirm no other attack or old interaction is affected.
13. Import/inspect a recording, explicitly replay it, compare replay/live labels, archive/restore,
    then reset only inactive synthetic `.pentest/` artifacts and confirm the stated preserved data.
14. Inspect empty, error, missing/log-disabled, truncated, model-unavailable, Docker-failure/host
    fallback states and cross-browser file import/SSE/focus (Chromium, Firefox, WebKit).
15. Inspect at least one real run/result per declared Codex model and attach the complete serial
    model × mode × profile matrix manifest. Capability requires a real independent confirmation.

Mark live, manual, cross-browser or Docker checks pending when not performed. Fix blocking defects,
rerun affected automated cases, and repeat failed manual steps before release approval.
